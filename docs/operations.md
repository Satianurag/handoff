# Backend operations and privacy

Operate through the authenticated Convex CLI and Dashboard. Consumer APIs never accept an operator flag or a caller-selected identity. Add `--prod` only when intentionally targeting production.

```sh
npx convex run operator:configure '{"key":"pauseAutomaticOperations","enabled":true}'
npx convex run operator:configure '{"key":"pauseAutomaticOperations","enabled":false}'
npx convex run recovery:run '{}'
npx convex run maintenance:privacy '{}'
npx convex run retention:sources '{}'
npx convex run retention:mail '{}'
```

The pause switch prevents new automatic generation, provider jobs, watch checks, notification dispatch, and retention sweeps. It does not undo an accepted provider request, cancel an already-running action, or stop expiry/access revocation. For a household, withdraw the relevant consent, revoke affected members, or request deletion through the authorized domain API. A source check uses public information; AI and email consents remain separate.

Initial adjustable product limits are `activeHouseholdWatches` 5 (supported maximum 100), `dailyHouseholdSourceChecks` 10, `dailyHouseholdSends` 20, `dailyPageOperations` 500, `dailyOutboundMessages` 100, `dailyModelInputTokens` 1,000,000, `dailyModelOutputTokens` 100,000, `demoActiveLimit` 10 and `demoDailyLimit` 30. These are product ceilings, not statements of purchased provider capacity. The model allowance reserves the model's verified possible usage before calling it, settles observed usage, and keeps uncertain usage reserved. Changing model allowances adjusts remaining capacity without clearing consumption, including when lowering the limit below already-reserved usage. Model windows start at UTC midnight; a legacy randomized window is re-anchored while carrying its stored debit. Other fixed-window settings take effect through the limiter's current-window balance and subsequent refills; use the pause switch for an immediate stop. No model quality overrides are used to fit an allowance.

The AgentMail account's observed Free limit was three inboxes. Auth uses one stable sender inbox per deployment; both development and production senders now exist, using two of the three observed slots. A synthetic household uses two inboxes: family and controlled office. Concurrent deployments/demos or real household mail can therefore exhaust capacity. Provisioning exposes a failure and supports an explicit idempotent retry. Increasing application quotas cannot increase provider entitlements. No upgrade or purchase was authorized or performed.

Generation uses the official Workflow component with concurrency one. Operational provider work uses a second instance with concurrency four. Explicit retry policies honor provider delays and avoid retrying permanent credential/validation failures. A send with an uncertain outcome is reconciled by its original identity; it is never sent again merely because a response was lost. Notifications contain a fixed generic subject/body and app link. Task names, household names, appointment details, and source text do not enter notification email.

Retention runs in bounded pages. Raw/projection mail and source text are eligible after 30 days. Active source references, unresolved conversation/active related work, pending proposals, current visit baselines, and unfinished handovers preserve evidence. Completed operational history is eligible after 90 days. Minimal send/delivery metadata remains after raw content is removed; a retired last receipt leaves an event-sequence baseline so historical events are not presented as new. Expired source cleanup deletes provider mail before removing local originals and quoted references. Provider errors retain a visible failed job and retryable cleanup state. A deletion receipt never asserts that external recipient copies were recalled.

Private household export uses authenticated NDJSON parts and rechecks requester identity, membership, and expiry on every download. It is a paginated export over an interval, not a frozen database snapshot. Household deletion immediately revokes access, stops queued work, waits for potentially running actions, removes the exclusive provider pod/inboxes, and purges domain records and exports. Scoped thread deletion retains separately confirmed responsibilities while removing originals, pending proposals, and quotations. Component Workflow journals contain IDs/minimal progress and are cleaned after completion. Firecrawl's single-page scrape/map actions do not create this component's durable crawl/page tables; this app does not use multi-page crawl storage. Provider-side public-page cache and contractual backup retention are separate from active application deletion.

For an incident, the operator should record the affected deployment and job IDs, pause new automation, revoke the affected access/consent, and preserve only the minimum diagnostic evidence needed. Review provider delivery receipts before any resend. Inspect failures without copying source bodies or credentials into tickets. Resume only after validating the affected boundary with a controlled synthetic case. Processor contracts, rights-contact details, and any legally required notifications need assessment for the actual operator and jurisdiction; this implementation makes no certification or legal-compliance claim.

Before accepting real household health information, supply the operator's real privacy/rights contact and review the processor contracts, retention terms, consent text, and applicable consumer-health/privacy obligations. Those business/legal decisions were not established by synthetic tests. Privacy, care-data, help and terms screens are now implemented locally; they accurately identify this as a synthetic evaluation release. The connected consumer app and controlled development journeys are implemented and verified. Current production rollout and post-deployment evidence are recorded in [implementation status](implementation-status.md); do not use historical backend-only reports as current production proof.

Static hosting uses the official `@convex-dev/static-hosting` component with app-owned root routing. `npm run build:web` now produces the real `dist/` frontend. Deploy the matching current backend and upload those assets with the component CLI; preserve exact auth discovery, webhook, private file and synthetic-fixture routes. Publication is authorized for this release; its actual outcome is recorded in [implementation status](implementation-status.md). A passing local build does not establish public routing, production authentication or provider capacity.


## Production release procedure

Build the frontend for the intended backend, never an implicit development URL. Public-config precedence is process `VITE_CONVEX_URL`, process `CONVEX_URL`, then `.env.local`’s `CONVEX_URL`; official Static Hosting supplies `VITE_CONVEX_URL` for its selected production target. The current production target is `https://admired-fish-176.convex.cloud`, with public hosting on the matching `.convex.site` origin. `npm run build:web` replaces `dist/`; `preview:web` reads the built config rather than regenerating it. The static host must serve the app bootstrap on supported deep links while preserving HTTP API routes and genuine missing-asset 404s. `npm run deploy` invokes official Static Hosting, builds `dist/` for production and publishes the matching backend/assets; `npm run deploy:backend` invokes only `convex deploy`. Inspect deployment selection before either command.

After deployment verify the public landing and direct signed-in routes, actual production config, no browser asset/console failures, verified sign-in, realtime shared mutation, private-file denial, and controlled provider paths. Remove the synthetic household through tracked deletion and observe all processors; do not delete unrelated real data or reset provider keys. Fresh production verification and cleanup belong in a sanitized release evidence report.

[Convex deployment documentation](https://docs.convex.dev/understanding/workflow) and [CLI environment/deploy reference](https://docs.convex.dev/cli) were also checked through Context7. Server secrets use `npx convex env set --prod`; only the public deployment URL belongs in static configuration.
